1. 概要と成果物

2.3 設計方針

  • 外部依存ゼロ: DirectXTK や stb_image を使わず、WIC と D3DCompiler など Windows SDK 標準のみで構成。
  • 実行時シェーダーコンパイル: HLSL は D3DCompileFromFile で起動時にコンパイル。シェーダーの修正に再ビルドが不要。
  • CPU 物理 + GPU 描画: SPH は CPU（OpenMP）で計算し、位置と速さのみを毎フレーム GPU へ転送（12,000 × 16 B = 192 KB）。
  • 頂点バッファ不要の描画: 粒子は SV_VertexID / SV_InstanceID からビルボードを生成し、フルスクリーンパスも 3 頂点の三角形を生成する。
  • フォールバック: 画像がなければノイズ生成、デバッグレイヤーがなければ通常デバイス、というように環境差で落ちない構成。

4. 地形生成（手続き的高さマップ）

地形は assets/terrain.obj があればそれを読み込み（6 章）、なければ本章の手続き生成を用いる。どちらの場合も最終的に「高さマップ + 描画メッシュ」という同じ形になる。

4.1 高さ関数

地形は y = h(x, z) の高さマップで表す。谷の中心線を正弦波の和で蛇行させ、中心からの距離に応じて山を立ち上げる。上流（−z）を高く、下流（+z）を低くして水が流れる勾配を作る。

c(z) = 4 sin(0.16 z) + 2 sin(0.41 z + 1.7)   （谷の中心線）
d = |x − c(z)|,   w = smoothstep(1.6, 8.5, d)   （0: 谷底, 1: 山）
h = −0.20 z + 0.3·min(d, 1.6)2 + 11 w + fBm(x, z)·(0.25 + 5 w) + ridged(x, z)·1.5 w
項役割
−0.20 z全体の傾斜（60 m で 12 m の落差、約 11°）
0.3·min(d,1.6)2谷底の浅い U 字断面。水を中央へ集める
11 w両側の山（smoothstep で滑らかに立ち上げ）
fBm × (0.25 + 5w)岩肌の凹凸。谷底は ±0.25 m、山肌は ±5 m と場所で振幅を変える
ridged × 1.5w稜線状の鋭い筋（尾根ノイズ）

4.2 ノイズ

Ken Perlin の Improved Noise（2002）を 2 次元化して実装。格子点にハッシュで勾配ベクトルを割り当て、評価点との内積を緩和曲線 6t5 − 15t4 + 10t3 で双線形補間する。

  • fBm: 周波数 2 倍・振幅 1/2 のノイズを 6 層重ね、振幅合計で正規化（−1〜1）。
  • 尾根状ノイズ: (1 − |noise|)2 を重ねる。ノイズが 0 を横切る場所に鋭い稜線が出る。
  • 周期版: 格子座標を周期で折り返し、タイリング可能なテクスチャを作る（5 章）。

4.3 メッシュ・法線・UV

  • 257×257 頂点、256×256 セル × 2 三角形 = 131,072 三角形、32bit インデックス。
  • 法線は中心差分 n = normalize(−∂h/∂x, 1, −∂h/∂z)。SPH の衝突にも同じ関数を使う。
  • UV = (x, z) × 0.12（約 8.3 m でテクスチャ 1 周、WRAP サンプリング）。
  • 三角形の巻き順は D3D 既定（画面上で時計回りが表面、左手系）に合わせ、上から見て時計回りに並べる。
  • 任意座標の高さは双線形補間 GetHeight(x, z) で返す（読み取り専用でスレッドセーフ）。

5. 岩テクスチャ（WIC 読み込みと手続き生成）

5.1 画像ファイルの読み込み（TextureLoader）

Windows Imaging Component（WIC）を用い、PNG / JPG / BMP / TIFF / GIF などを外部ライブラリなしで読み込む。

  1. CoInitializeEx → IWICImagingFactory を静的に 1 回生成
  2. CreateDecoderFromFilename でファイルを開き、先頭フレームを取得（形式は拡張子でなく内容で判定）
  3. IWICFormatConverter で 32bpp RGBA に統一（パレット・グレースケール・CMYK も吸収）
  4. CopyPixels でメモリへ展開（行ピッチ = 幅 × 4）
  5. MipLevels = 0 + D3D11_RESOURCE_MISC_GENERATE_MIPS でテクスチャを作成し、レベル 0 に UpdateSubresource、GenerateMips で縮小版を自動生成

assets/rock.png → rock.jpg → rock.jpeg → rock.bmp の順に探し、すべて失敗した場合は 5.2 の手続き生成に切り替える。タイトルバーに出所（画像 / ノイズ生成）を表示する。

5.3 サンプリングとシェーディング（Terrain.hlsl）

  • サンプラー: 異方性フィルタ 8 × WRAP。斜めから見る谷の壁でもぼけにくい。
  • 繰り返し感の低減: 別スケール（×0.23、オフセット 0.31）でもう一度サンプルして乗算する。
  • 陰影: ランバート拡散反射 max(0, N·L) + 半球環境光（上向きほど明るい）+ 谷底の暗色化。光源方向は (−0.35, 0.85, 0.45) を正規化。

6. OBJ 地形の取り込み（Blender 連携）

6.1 目的と方式

手続き生成の地形に加え、Blender などの DCC ツールで作ったメッシュを地形として使えるようにした。方式は「メッシュはそのまま描画し、衝突判定用には真上から高さマップに焼き込む」というハイブリッドである。SPH 側は既存の GetHeight / GetNormal をそのまま使うため、物理コードの変更なしに任意形状の地形を扱える。

6.2 OBJ ローダー（MeshLoader）

Wavefront OBJ は行指向のテキスト形式で、外部ライブラリなしで読める。対応要素と処理は次のとおり。

行内容処理
v x y z頂点座標一時配列に蓄積
vt u vテクスチャ座標v ← 1 − v（OBJ は左下原点、D3D は左上原点）
vn x y z法線蓄積。無ければ後で面積重み付きスムーズ法線を計算
f a/b/c …面a / a/b / a//c / a/b/c と負の相対インデックスに対応。(v, vt, vn) の組をキーに頂点を共有し、4 頂点以上は扇状 (0, i, i+1) に三角形化
o g s usemtl mtllibその他無視（材質は本プログラム側の岩テクスチャを使う）

OBJ では「座標が同じでも UV や法線が異なれば別頂点」なので、(v, vt, vn) の三つ組をハッシュマップのキーにして頂点を生成・再利用する。試作用の谷（121×121 頂点、14,400 四角形）は約 2 MB で、読み込みは数十 ms。

6.3 座標系の変換

Blender は右手系・Z-up、DirectX は左手系・Y-up である。変換は 2 段階で行う。

  1. エクスポート時（Blender 側）: 「Forward: −Z, Up: Y」を指定すると Blender (x, y, z) → OBJ (x, z, −y) と軸が入れ替わり、右手系 Y-up になる。
  2. 読み込み時（本プログラム）: 右手系 → 左手系にするため x を反転する（位置と法線）。
Blender (x, y, z) → OBJ (x, z, −y) → DirectX (−x, z, −y)

結果として Blender の上面図で「上 (+Y)」が奥（上流、−z）、「右 (+X)」が画面右になり、Blender で見たままの構図でカメラに映る。

巻き順の統一: 鏡映変換で三角形の巻き順が反転し、さらに元データの巻き順は保証されない。そこで三角形ごとに cross(e1, e2).y を計算し、負（下向き）なら頂点 1, 2 を入れ替える。地形は「上から見える面が表」なので、4 章のメッシュと同じ規約（左手系 + 時計回りが表 ⇔ cross.y > 0）に揃う。

6.4 自動フィット

SPH のパラメータ（粒子間隔 0.3 m、地形 60 m 四方）に合わせるため、読み込んだメッシュのバウンディングボックスから一様スケールを決める。

s = 0.999 · WORLD_SIZE / max(Δx, Δz),   p ← (p − center) · s

xz の大きい方の辺が 60 m になり、中心が原点に来る。高さも同じ倍率で拡縮されるので、Blender 側では縦横比だけ意識すればよい。0.999 は端の頂点が高さマップ格子の外に出ないための余裕である。

6.5 高さマップへの焼き込み（BakeHeightMap）

衝突判定は高さマップ（257×257）で行うため、メッシュを真上から「ラスタライズ」して各格子点の高さを求める。

heights[*] = 未設定
for 各三角形 (p0, p1, p2):
    xz 平面に投影し、包含する格子範囲 [ix0, ix1] × [iz0, iz1] を求める
    for 範囲内の各格子点 (x, z):
        辺関数で重心座標 (w0, w1, w2) を計算
        if w0, w1, w2 ≥ −ε:                       # 三角形の内側 (辺上を含む)
            y = w0·p0.y + w1·p1.y + w2·p2.y
            heights[x, z] = max(heights[x, z], y)  # 上から見える面を採用
for 未設定の格子点:  覆われた 4 近傍の平均で埋める (全て埋まるまで反復)
  • 重心座標は辺関数（2D の外積）を面積で割って求める。面積 ≈ 0 の縮退三角形（真横を向いた面）はスキップ。
  • max を取るため、オーバーハングがあっても上面のみが残る（下面は衝突に使われない）。
  • メッシュが正方形でない場合や穴がある場合、未被覆の格子点は隣接平均で外挿される（平坦に延長）。
  • 計算量は O(三角形数 × 各三角形の包含格子点数)。14,400 四角形で数 ms。

6.6 エミッタ位置の決定

手続き生成では谷の中心線 c(z) を式で持っていたが、任意メッシュでは使えない。Terrain::GetValleyCenterX(z) を導入し、OBJ 地形では「その z の行で高さが最も低い x」を高さマップから線形探索する（端 1 m は除外）。エミッタは上流端 z = −27.5 でこの関数を呼ぶため、谷がどこにあっても水はその谷底に投入される。

6.8 制約

  • 高さマップ方式のため、洞窟やひさし状のオーバーハングの下面には衝突しない。必要なら符号付き距離場（SDF）を構築し、SPH の衝突処理を「最近傍面への押し戻し」に置き換える（16 章）。
  • 高さマップ解像度は 257×257（約 0.23 m 刻み）。これより細かい段差は平滑化される。
  • 地形シェーダーの谷底暗色化（y + 0.2z による）は手続き生成の傾斜を前提にしており、OBJ 地形では見た目上の近似になる。

7. SPH 流体シミュレーション

7.1 SPH の基本式

SPH（Smoothed Particle Hydrodynamics）は流体を粒子で離散化し、任意の物理量 A を近傍粒子の値をカーネル W で重み付けした和で近似する。

A(x) ≈ Σj mj (Aj / ρj) W(|x − xj|, h)

本実装は Müller et al.（2003）の WCSPH（弱圧縮性 SPH）に従う。

密度:  ρi = Σj m Wpoly6(rij, h)
圧力（状態方程式）:  pi = k · max(ρi − ρ0, 0)
圧力力:  fip = −Σj≠i m (pi + pj) / (2ρj) ∇Wspiky(rij, h)
粘性力:  fiv = μ Σj≠i m (vj − vi) / ρj ∇2Wvisc(rij, h)
加速度:  ai = (fip + fiv) / ρi + g

圧力を max(·, 0) で打ち切るのは、負圧（引力）による粒子の凝集を防ぐためである（自由表面付近では密度が ρ0 を下回るため）。

7.2 カーネル関数

Wpoly6(r) = 315 / (64πh9) · (h2 − r2)3   (0 ≤ r ≤ h)
∇Wspiky(r) = −45 / (πh6) · (h − r)2 · r̂   (0 < r ≤ h)
∇2Wvisc(r) = 45 / (πh6) · (h − r)   (0 ≤ r ≤ h)
  • poly6 は平方根不要で密度計算が軽い。
  • spiky は r → 0 で勾配が消えないため、粒子が重なったときにも斥力が働く（poly6 の勾配だと 0 になり粒子が凝集する）。
  • visc のラプラシアンは常に正で、速度差を必ず減らす方向に働く（数値的に安定）。
  • 係数は h から起動時に事前計算する。

7.3 パラメータの設計

量値根拠
粒子間隔 s0.30 m谷底幅 ≈ 3.2 m に約 10 個並ぶ粒度
平滑化半径 h0.60 m = 2s静止状態で約 33 個の近傍を持つ
質量 mρ0 s3 = 27 kg粒子 1 個が占める体積 × 水の密度
剛性 k2000音速 c = √k ≈ 45 m/s。深さ 1 m で圧縮率 0.5%（ρ g H / k）
粘性 μ0.40実際の水より大きいが、流れをまとめ数値振動を抑える

7.4 時間積分

シンプレクティック・オイラー法（速度を先に更新してから位置を更新）を用いる。エネルギーが長期的にドリフトしにくく、SPH の標準的な選択である。

vi ← vi + ai Δt,   xi ← xi + vi Δt

1 フレームで ceil(frameTime / Δt) 回のサブステップを実行するが、上限 maxSubsteps = 5 で頭打ちにする。処理落ち時にサブステップが増えてさらに遅くなる「死のスパイラル」を防ぎ、その場合は実時間より遅く進行する。

7.5 1 サブステップの処理順

Emit(dt)                  エミッタ: spacing/emitSpeed 秒ごとに 14×4 の粒子板を上流に置く
BuildGrid()               空間ハッシュ格子の構築（8 章）
BuildNeighborLists()  ‖   近傍リスト作成（27 セル走査、最大 96 個）
ComputeDensityPressure() ‖ 密度・圧力
ComputeForces()       ‖   圧力力 + 粘性力 → 加速度クランプ → 重力
Integrate()           ‖   速度・位置更新 → ResolveCollision（9 章）
RemoveDrained()           下流端を越えた粒子を末尾と入れ替えて削除

‖ は OpenMP parallel for（schedule(dynamic, 64)）で並列化した処理。粒子ごとに独立して書き込むため競合がない。

7.6 エミッタと排水

  • 上流端 z = −27.5 の谷の中心に、粒子板（横 14 × 縦 4）を初速 4 m/s（+z）で投入。板同士が重ならないよう「板が 1 粒子間隔進む時間 = s / vemit = 0.075 s」ごとに投入する（約 750 粒子/秒）。
  • 格子配置の規則性を崩すため各粒子に ±15% のジッタ（xorshift 乱数）を加える。
  • 下流端 z > 29.5 に達した粒子は配列末尾と入れ替えて削除（O(1)）。最大 12,000 個で定常流になる。

8. 近傍探索（空間ハッシュ + カウンティングソート）

SPH の計算量は近傍探索に支配される。全粒子対を調べると O(N2) = 1.4 億対 / ステップとなり実用にならないため、一辺 h の格子で空間を分割し、周囲 27 セルのみを調べる。

8.1 空間ハッシュ

セル座標: (cx, cy, cz) = ⌊x / h⌋
ハッシュ: key = (cx · 73856093) ⊕ (cy · 19349663) ⊕ (cz · 83492791) & (tableSize − 1)

Teschner et al.（2003）の大きな素数によるハッシュ。無限に広い空間を固定サイズ（粒子数の 2 倍以上の 2 のべき乗 = 32768）の表に写像するため、地形全体を格子で埋める必要がない。剰余の代わりにビットマスクを使う。

8.2 カウンティングソート

1. 各粒子のセル座標とハッシュ値を計算                       (並列)
2. cellStart[key + 1]++  でハッシュ値ごとの粒子数を数える
3. 累積和  cellStart[k+1] += cellStart[k]  → 各ハッシュ値の開始位置
4. sorted[cellStart[key] + fill[key]++] = i  で粒子番号を振り分け

結果、ハッシュ値 key のセルに属する粒子は sorted[cellStart[key] .. cellStart[key+1]) で連続して取り出せる。動的メモリ確保がなく、毎ステップ O(N + tableSize) で再構築できる。

8.3 近傍リストのキャッシュとハッシュ衝突対策

  • 密度計算と力計算は同じ近傍を使うため、走査を 1 回にまとめて粒子ごとに最大 96 個の近傍番号を記録する（BuildNeighborLists）。走査コストが半減し、実測で約 3 倍の高速化。
  • 異なるセルが同じハッシュ値を持つと、27 セル走査で同じ粒子を 2 回数える危険がある。候補粒子のセル座標が「今調べているセル座標」と一致するかを確認して除外する。
  • 距離判定は r2 < h2 で行い平方根を避ける。

9. 境界処理と安定化

9.1 地形との衝突

粒子中心が「地面の高さ + 粒子半径」より低ければ、その高さまで押し戻し、地面法線 n に対してめり込む速度成分を除去する。

y ← h(x, z) + s/2,   v ← v − (1 + e)(v·n)n  (v·n < 0 のとき),   v ← (1 − μf)v

e = 0（反発なし）、μf = 0.01/ステップ。側壁（x = ±29.5）と上流壁（z = −29.5）も同様に処理する。

9.2 谷からの飛び出しを防ぐ 3 つの安定化

初期実装では壁際で密度が急上昇したときの圧力の「蹴り」で粒子が谷の外へ飛散した。以下の 3 手法で解消した。

手法内容パラメータ
加速度クランプ圧力・粘性による加速度の大きさを上限で打ち切る（重力は別に加算）。1 ステップの速度変化を 0.75 m/s 以下に制限maxAcceleration = 250
接触ゾーン減衰地面から 0.3 m 以内の粒子を、地面に近いほど強く減衰（最下部で 6%/ステップ、上端で 0 に線形減少）。壁に当たった粒子の跳ね上がりを抑えるcontactZone = 0.30, contactDamping = 0.06
孤立粒子の空気抵抗近傍が 8 個未満の粒子（飛沫）に 1.5%/ステップの減衰。勢いを失いすぐ流れに戻るairDrag = 0.015, sparseNeighbors = 8

このほか安全弁として速度上限 10 m/s、密度 0 除算防止（r2 < 10−12 の粒子対を除外）を設けている。

9.3 境界密度の欠損について

地面の下には粒子が存在しないため、接地粒子の密度は本来より低く見積もられる（境界密度欠損）。本実装は境界粒子を置かず、衝突処理と接触ゾーン減衰で吸収している。より厳密には Akinci らの境界粒子法や ghost particle が有効である（16 章）。

10. 粒子のレンダリング（スフィア・インポスター）

10.1 ビルボード生成

粒子ごとに 4 頂点の四角形を頂点バッファなしで生成する。DrawInstanced(4, N) を発行し、頂点シェーダーで SV_InstanceID から粒子を、SV_VertexID から四隅（−1,−1）(−1,1)(1,−1)(1,1) を選ぶ。四角形はビュー空間で作るため常にカメラに正対する。

float4 p = Particles[iid];                        // StructuredBuffer<float4> (xyz: 位置, w: 速さ)
float3 centerV = mul(float4(p.xyz, 1), View).xyz;
float3 posV = centerV + float3(corners[vid] * radius, 0);
o.posH = mul(float4(posV, 1), Proj);

10.2 球面の再構成と正しい深度

ピクセルシェーダーで四角形内座標 uv（−1〜1）から球面上の点を求める。左手系ビュー空間ではカメラは +z を向くので、カメラ側の半球は nz < 0。

r2 = u2 + v2 > 1 → discard
n = (u, v, −√(1 − r2)),   pV = cV + n R
depth = (pV · Proj).z / (pV · Proj).w → SV_Depth

SV_Depth に球面の深度を書くことで、平面の四角形でありながら球同士・地形と正しく交差する。早期 Z は無効になるが、粒子数 12,000 程度では問題にならない。

10.3 速度による着色

  • 参考動画に合わせ、速さ 0〜6 m/s を「濃青 → 水色 → 緑 → 黄 → 赤」の 5 色制御点の区間線形補間（Jet 風カラーマップ）で表す。
  • SPH の速度は粒子ごとに細かく揺らぐため、そのまま着色すると色がまだらになる。CPU 側で近傍リストを使い「自分と近傍の速さの平均」を描画用の速さとして渡す（GetRenderData）。物理には影響しない。
  • 陰影は拡散反射 + Blinn-Phong 鏡面反射（指数 40）。

11. 表面生成（スクリーンスペース流体レンダリング）

粒子群から陽なメッシュ（Marching Cubes 等）を作る代わりに、画面空間で深度を平滑化して法線を復元する手法（van der Laan, Green, Sainz 2009）を簡略化して実装した。3 パスで構成される。

11.1 パス 1: 深度

粒子を 10 章と同じ球インポスターで描き、色の代わりにビュー空間の z を R32_FLOAT テクスチャに出力する。メインの深度バッファ（地形描画済み）と組で描くため、地形の後ろの粒子は自動的に隠れる。テクスチャは 0 でクリアし、0 = 流体なしとして扱う。表面用の球半径は粒子間隔の 1.3 倍とし、隣の球と重なって隙間を作らない。

11.2 パス 2: バイラテラルぼかし（分離可能）

wk = exp(−k2 / 2σs2) · exp(−(dk − d0)2 / 2σd2),   d′ = Σ wk dk / Σ wk
  • 半径の透視補正: ワールド半径 0.9 m を画面に投影したピクセル数 radiusPx = 0.9 / d0 · Proj11 · H/2 を使う（2〜24 px）。近い流体ほど広く、遠い流体ほど狭くぼかすため見た目の滑らかさが距離に依らない。
  • 流体外の除外: d ≤ 0（流体なし）のサンプルは重みに入れない。これにより輪郭が内側へ縮まず、地形との境界がぼけない。
  • 深度 σ = 1.5 m と大きめ。流体外は上記で除外済みなので、球の凹凸（≤ 0.4 m）を確実に平滑化できる。初期値 0.35 では球が個別に残り「ブロック状」の見た目になった。
  • 横 → 縦の分離可能フィルタを 4 回反復（計 8 パス）。1 パスあたり最大 49 タップ。

11.3 パス 3: 法線復元と合成

ぼかした深度からビュー空間座標を復元し、隣接ピクセルとの差分から法線を求める。

p(u, v, d) = (ndcx · d / Proj00,  ndcy · d / Proj11,  d)
∂p/∂x = 左右どちらか |Δz| の小さい側,   ∂p/∂y = 上下どちらか |Δz| の小さい側
n = normalize(∂p/∂x × ∂p/∂y)

差の小さい側を採用するのは、流体の輪郭（深度が飛ぶ場所）で法線が壊れるのを避けるためである。ピクセルの +y は下向き = ビュー空間の −y なので、外積 (+x) × (−y) = −z がカメラ側を向く法線になる。

陰影は水らしさを出すため 3 成分を合成し、α = 0.9 のアルファブレンドで地形の上に描く。

拡散: Cw(0.5 + 0.5 max(0, n·L)),   鏡面: 0.35 · max(0, n·H)48
フレネル（Schlick）: F = 0.06 + 0.94 (1 − n·V)4 → 空色を F · 0.5 で混合

Cw = (0.64, 0.68, 0.78) は参考動画の灰青色に合わせた。

12. 描画パイプラインと定数バッファ

12.1 定数バッファ（b0）

全シェーダーで 1 つの cbuffer CBFrame（320 バイト）を共有する。C++ 側 FrameConstants と配置を一致させ、static_assert で 16 バイト境界を検証している。

行列の転置について: DirectXMath は行優先で v′ = v M の規約、HLSL の既定は列優先パッキング。CPU 側で転置して転送すると、HLSL で mul(float4(v,1), M) と書け、M._m00, M._m11 も数学どおりの要素になる（法線復元で使用）。

16. 既知の制約と拡張案

制約拡張案
CPU SPH のため粒子数は 1〜2 万が上限コンピュートシェーダーへ移植（格子構築は GPU 基数ソート、密度・力はスレッドグループ単位）。10 万粒子以上が可能
WCSPH は圧縮率が k に依存し、k を上げると Δt が小さくなるPCISPH / IISPH / DFSPH など圧力を反復で解く非圧縮手法
境界密度の欠損を減衰で吸収しているAkinci et al.（2012）の境界粒子（地形表面に粒子をサンプリングして密度に寄与させる）
水面は不透明に近い α = 0.9 で厚みを考慮していない厚みパス（加算ブレンドで粒子の厚さを蓄積）による透過率・屈折の計算
スクリーンスペース法は視点依存で、画面外の情報がないMarching Cubes / 異方性カーネル（Yu & Turk 2013）による陽なメッシュ生成
表面張力なしAkinci らの凝集力モデル、または負圧の一部を許容
地形は高さマップ（OBJ 取り込み時もオーバーハング下面は不可）符号付き距離場（SDF）による任意形状との衝突
