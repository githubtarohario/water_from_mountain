第 II 部

地形編

乱数から「自然に見える形」を作るノイズの技術、
高さマップによる地形、テクスチャ、そして Blender からのモデル取り込み。

第 5 章

ノイズと手続き的生成

山や岩、雲のような自然物は「規則的でもなく、完全にランダムでもない」形をしています。この章では、そのような形をプログラムで作るための基本部品、パーリンノイズとその重ね合わせ（fBm）を、数式と実装の両面から学びます。

5.1 乱数ではダメな理由

地形の高さを各点で乱数にすると、隣り合う点の高さが無関係になり、砂嵐のような画像になります。自然な起伏に必要なのは「近くの点は似た値、遠くの点は無関係」という連続性のあるランダムです。これを作るのがノイズ関数で、CG では Ken Perlin が 1985 年に考案し 2002 年に改良したパーリンノイズが標準的に使われます。

5.2 パーリンノイズの仕組み

図 5-1 2 次元パーリンノイズ

格子点ごとの勾配ベクトルは、座標から置換テーブル（0〜255 をシャッフルした配列）を引いて決めます。同じ座標には常に同じ勾配が対応するので、乱数と違って何度評価しても同じ値になります（再現性）。

5.3 fBm — 大小の起伏を重ねる

パーリンノイズ 1 層は「なめらかな丘」程度の起伏しか作れません。周波数を 2 倍、振幅を 1/2 にしたノイズを何層も足すと、大きなうねりの上に細かい凹凸が乗った、自然な地形や雲の形になります。これを fBm（fractional Brownian motion）と呼び、各層をオクターブと呼びます。

fBm(x) = Σi=0n−1 gi · noise(li x) / Σ gi  （l = lacunarity ≈ 2, g = gain ≈ 0.5）

5.4 尾根状ノイズ

ノイズの絶対値を取って 1 から引く（1 − |noise|）と、ノイズが 0 を横切る場所に鋭い「尾根」が現れます。これを重ねた尾根状ノイズ（ridged multifractal）は、山の稜線や岩の亀裂の表現に向いています。本プログラムでは 2 乗して尾根をさらに細くしています。

第 6 章

高さマップ地形の設計と生成

地形をどう表現し、どう「蛇行する谷のある山」にデザインし、どうやって GPU が描ける三角形の集まりにするか。この章では高さマップという表現と、そこからメッシュ・法線・テクスチャ座標を作る手順を学びます。作った高さマップは、第 12 章で粒子の衝突判定にも使います。

6.1 高さマップという表現

地形のように「どの (x, z) にも高さが 1 つ決まる」形は、2 次元配列 h[ix][iz] で表せます。これが高さマップです。メモリが少なく、任意の点の高さを補間で即座に取れ、法線も簡単に求まります。欠点は、ひさし状の張り出し（オーバーハング）や洞窟を表せないことです。

本プログラムでは 257×257 の格子で 60 m × 60 m を覆います（1 セル ≈ 0.23 m）。格子点 (ix, iz) のワールド座標は x = −30 + ix · 0.234 のように線形に対応します。

6.2 谷のある山をデザインする

「蛇行する谷を水が流れ落ちる」ために、高さ関数を部品に分けて設計します。

N = normalize(−∂h/∂x, 1, −∂h/∂z),   ∂h/∂x ≈ (h(x+e, z) − h(x−e, z)) / 2e

第 7 章

テクスチャの生成と画像ファイルの読み込み

岩肌の模様は、画像ファイルを読み込む方法と、ノイズから計算で作る方法の 2 通りを実装しています。この章では、CPU 上のピクセル配列を GPU テクスチャにする共通の手順、WIC による画像読み込み、そしてノイズによる手続き的テクスチャを学びます。

7.1 ピクセル配列から GPU テクスチャへ

どちらの方法でも最終的には「RGBA 各 8bit のピクセルが幅 × 高さ個並んだ配列」ができ、それをテクスチャにします。ミップマップも同時に作ります。

  • UpdateSubresource はレベル 0 だけに書き、GenerateMips が残りを縮小して埋めます。

7.2 WIC による画像ファイルの読み込み

Windows には画像コーデック基盤 WIC（Windows Imaging Component）が標準搭載されており、PNG / JPEG / BMP / TIFF / GIF などを追加ライブラリなしで読めます。COM ベースの API なので手順はやや長いですが、流れは単純です。

  1. ファクトリ IWICImagingFactory を作る（COM 初期化が必要）
  2. CreateDecoderFromFilename でファイルを開く。形式は拡張子でなく内容で判定される
  3. 先頭フレームを取り出す（アニメ GIF などは複数フレーム）
  4. IWICFormatConverter で 32bpp RGBA に統一（元がパレット・グレー・CMYK でも吸収）
  5. CopyPixels でメモリに展開し、7.1 の手順でテクスチャ化
{{CODE:src/TextureLoader.cpp: bool LoadFromFile(Graphics& gfx, const std::wstring& path,: }}}

Terrain::CreateRockTexture は assets/rock.png → rock.jpg → … の順に読み込みを試し、すべて失敗すれば手続き生成に切り替えます。「無ければ落ちる」ではなく「無ければ代替」という設計は、配布時のトラブルを減らします。

第 8 章

外部メッシュの取り込み — OBJ と Blender

自分で式を書く代わりに、Blender などのツールで作った地形を使いたいこともあります。この章では、最も単純な 3D ファイル形式である Wavefront OBJ の読み方、座標系の変換、そして「メッシュを高さマップに焼き込む」ことで衝突判定を変えずに任意形状を扱う方法を学びます。

8.1 OBJ 形式

OBJ は行ごとに要素を書くテキスト形式です。

v  -30.0  6.19  30.0      # 頂点座標 (1 番から数える)
vt 0.0 0.0                # テクスチャ座標
vn 0.0 1.0 0.0            # 法線
f  1/1/1 2/2/2 123/123/123 122/122/122   # 面: 頂点/UV/法線 の番号の組 (4 頂点以上も可)

面の各頂点は a, a/b, a//c, a/b/c の 4 通りの書き方があり、負の数は「末尾から数えて」の相対指定です。Blender は既定で四角形（quad）を出力するので、三角形化が必要です。

頂点の共有

OBJ では位置・UV・法線が別々の配列で、面の頂点は「その組み合わせ」を指します。GPU の頂点は 1 つの構造体なので、(v, vt, vn) の組ごとに頂点を作り、同じ組が再登場したら再利用します。ハッシュマップで管理します。

{{CODE:src/MeshLoader.cpp: bool LoadObj(const std::wstring& path, MeshData& out, std::string* errorMsg): }}}

多角形の三角形化は扇状分割（0, i, i+1）です。凸な多角形なら常に正しく、Blender の quad はほぼ凸なので実用上十分です。

8.2 座標系の変換

Blender は右手系・Z 上、本プログラムは左手系・Y 上です。変換は 2 段階で行います。

Blender (x, y, z) —エクスポート (Forward −Z, Up Y)→ OBJ (x, z, −y) —読み込み時 x 反転→ DirectX (−x, z, −y)

1 段目は Blender のエクスポート設定で、Y を上にする軸の入れ替えです。これで右手系 Y-up になります。2 段目で x を反転すると左手系になります（鏡映は右手系と左手系を入れ替えます）。結果として、Blender の上面図で上 (+Y) が奥（上流）、右 (+X) が画面の右になり、Blender で見たままの構図で表示されます。

巻き順の統一

鏡映すると三角形の巻き順が反転します。さらに元データの巻き順は保証されません。そこで三角形ごとに e1 × e2 の y 成分を調べ、負（下向き）なら頂点 1, 2 を入れ替えます。地形は「上から見える面が表」なので、これで第 6 章のメッシュと同じ規約に揃います。

8.3 自動フィット

SPH のパラメータ（粒子間隔 0.3 m、地形 60 m）に合わせるため、バウンディングボックスから一様スケールを決め、中心を原点に移します。高さも同じ倍率なので、Blender 側では縦横の比だけ意識すれば十分です。

8.4 高さマップへの焼き込み

衝突判定は高さマップで行うので、メッシュを真上から「ラスタライズ」して格子点の高さを求めます。手順は GPU のラスタライザと同じ考え方です。

  1. 三角形を xz 平面に投影し、包含する格子範囲を求める
  2. 範囲内の各格子点で重心座標（辺関数 ÷ 面積）を計算し、3 つとも ≥ 0 なら内側
  3. 高さを重心座標で補間し、既存値より高ければ採用（上から見える面）
  4. 覆われなかった格子点は、隣接点の平均で反復的に穴埋め
w0 = ((x1−px)(z2−pz) − (x2−px)(z1−pz)) / area,  w1 = …,  w2 = 1 − w0 − w1
y = w0y0 + w1y1 + w2y2
{{CODE:src/Terrain.cpp:void Terrain::BakeHeightMap(const MeshLoader::MeshData& mesh):}}
コラム: 重心座標 三角形の内部の点 P は、3 頂点の「重み付き平均」 P = w0A + w1B + w2C（w の和は 1）で一意に表せます。重みは「P と対辺が作る小三角形の面積 ÷ 全体の面積」に等しく、すべて 0 以上なら P は内側です。GPU が三角形内で頂点属性を補間するときも、まさにこの重心座標を使っています。
