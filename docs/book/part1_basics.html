第 1 章

3D グラフィックスの数学 — 座標系・ベクトル・行列・変換

3D 空間の点をどうやって画面の 2D に映すのか。この章では、CG のあらゆる場面で使う「座標系」「ベクトル」「行列」と、ワールド → ビュー → 射影という変換の連鎖を、このプログラムのカメラのコードを題材に学びます。

1.1 座標系 — 右手系と左手系

3D 空間の位置は (x, y, z) の 3 つの数で表します。ただし「どちらが上か」「奥行きはどちらが正か」には流儀があり、これを座標系と呼びます。本プログラムは DirectX の慣習に従い、Y 軸が上、左手系を使います。

図 1-1 右手系と左手系。x を右、y を上にしたとき、z が手前を向くか奥を向くかが違う

左手系では、左手の親指を +x、人差し指を +y に向けたとき、中指が +z を指します。カメラは +z の方向を見る（奥ほど z が大きい）ため、奥行き = z と素直に対応するのが利点です。Blender は右手系・Z が上なので、モデルを持ち込むときは変換が必要です（第 8 章）。

ポイント 座標系の違いは「符号の向き」だけですが、外積の向き、三角形の表裏（巻き順）、回転の正方向のすべてに影響します。本書では左手系で統一し、右手系のデータを扱うときは明示的に変換します。

1.2 ベクトルの演算

ベクトルは「大きさと向き」を持つ量で、位置・速度・力・法線などすべてベクトルで表します。CG で頻出する演算は次の 4 つです。

演算定義CG での用途
加減・スカラー倍(ax ± bx, …)、ka位置の移動、速度の積分 x ← x + vΔt
長さ・正規化|a| = √(ax2 + ay2 + az2)、â = a/|a|距離判定、方向だけを取り出す（法線・光源方向）
内積a·b = axbx + ayby + azbz = |a||b| cos θ2 ベクトルのなす角、明るさ（N·L）、射影
外積a×b = (aybz − azby, azbx − axbz, axby − aybx)2 ベクトルに垂直なベクトル（面の法線）、三角形の表裏判定

内積は特に重要です。単位ベクトル同士の内積は cos θ そのもので、「どれくらい同じ向きか」を −1〜1 で表します。第 4 章のライティングでは、面の法線 N と光の方向 L の内積で明るさを決めます。

外積は「2 つのベクトルが張る平面に垂直なベクトル」を返し、その長さは平行四辺形の面積に等しくなります。地形メッシュの法線計算（第 6 章、第 8 章）や三角形の向きの判定に使います。左手系では、a から b へ左手の指を曲げたとき親指の向きが a×b です。

プログラムでは DirectXMath ライブラリの XMVECTOR（SIMD レジスタに載る 4 成分ベクトル）と XMFLOAT3（メモリ格納用）を使い分けます。例えばカメラのパン操作では、視線方向と上方向の外積で「右方向」を作っています。

1.3 行列と変換

「点を移動する」「回転する」「拡大縮小する」といった操作は、4×4 の行列 M を点に掛けることで表せます。3D なのに 4×4 を使うのは、平行移動を掛け算で表すためで、点は (x, y, z, 1) の 4 成分（同次座標）として扱います。

平行移動 T(t) : (x, y, z, 1) → (x+tx, y+ty, z+tz, 1)
拡大縮小 S(s) : (x, y, z, 1) → (sxx, syy, szz, 1)
y 軸回転 Ry(θ) : (x, z) → (x cosθ + z sinθ, −x sinθ + z cosθ)

行列の便利な性質は合成できることです。「回転してから移動」は R と T の積 1 つで表せ、何千個の頂点にも同じ 1 つの行列を掛ければ済みます。ただし積の順序を入れ替えると結果が変わります（回転してから移動 ≠ 移動してから回転）。

行ベクトルと列ベクトル DirectXMath は「行ベクトル × 行列」（v′ = vM）の規約で、変換は左から右へ v W V P と並びます。数学の教科書や OpenGL は「行列 × 列ベクトル」（v′ = Mv）で、順序が逆になります。どちらも同じ計算ですが、行列をメモリに置く順（行優先 / 列優先）と組み合わさって混乱のもとになります。第 3 章で GPU に渡すときの「転置」として再登場します。

1.4 変換の連鎖 — ワールド・ビュー・射影

3D の頂点が画面に映るまでには、3 つの座標系を経由します。

図 1-2 頂点が画面に映るまでの座標変換
  • ワールド行列 W: 物体をシーン内に置く（位置・向き・大きさ）。本プログラムの地形は最初からワールド座標で頂点を作るため単位行列（変換なし）です。
  • ビュー行列 V: 「カメラが原点にあって +z を向いている」状態になるよう、世界全体を動かす行列。XMMatrixLookAtLH(位置, 注視点, 上方向) で作ります。
  • 射影行列 P: 遠近感を付け、画面の範囲を −1〜+1 に正規化する。XMMatrixPerspectiveFovLH(画角, アスペクト比, near, far)。

透視投影の仕組み

遠くのものほど小さく見える「遠近感」は、ビュー座標の x, y を奥行き z で割ることで生まれます。射影行列はこの割り算の準備をする行列で、変換後の 4 成分目 w に z が入ります。GPU はラスタライズの直前に自動的に x/w, y/w, z/w を計算します（透視除算）。

xndc = xview · P00 / zview,   yndc = yview · P11 / zview
P00 = 1 / (aspect · tan(fovy/2)),   P11 = 1 / tan(fovy/2)

この式は第 15 章で「画面の深度から 3D 位置を逆算する」ときに、そのまま逆向きに使います。

深度値

変換後の z/w は 0（near 面）〜1（far 面）の深度値になり、手前の物体が奥の物体を隠す判定（深度テスト、第 2 章）に使われます。深度値は z に対して線形ではなく、近くに精度が集中します。near を小さくしすぎると遠くの精度が落ちて「Z ファイティング」（面がちらつく）が起きるため、本プログラムでは near = 0.5、far = 400 としています。

1.5 オービットカメラ

本プログラムのカメラは、注視点の周りを回る「オービットカメラ」です。カメラの位置を極座標（水平角 θ、仰角 φ、距離 D）で持ち、そこから直交座標を計算します。

pos = target + D (cosφ sinθ,  sinφ,  cosφ cosθ)
{{CODE:src/Camera.cpp:XMFLOAT3 Camera::GetPosition() const:}}

マウスのドラッグ量を θ, φ の増分に変換すれば回転、ホイールで D を倍率で変えればズームになります。φ を ±89° に制限しているのは、真上（90°）で視線と上方向ベクトルが平行になり LookAt が壊れるのを防ぐためです。

第 2 章

レンダリングパイプラインと DirectX 11

GPU は「頂点の集まり」をどのような手順で「画面のピクセル」に変えるのでしょうか。この章ではその手順（レンダリングパイプライン）を学び、DirectX 11 という API でそれをどう操作するのかを、初期化コード Graphics.cpp に沿って理解します。

2.1 レンダリングパイプラインの全体像

図 2-1 レンダリングパイプライン（本プログラムで使う段のみ）
  1. 入力アセンブラ (IA): 頂点バッファとインデックスバッファから頂点を読み、三角形に組み立てる。
  2. 頂点シェーダー (VS): 頂点ごとに実行される小さなプログラム。主に座標変換（第 1 章）を行い、クリップ座標を出力する。
  3. ラスタライザ (RS): 透視除算、ビューポート変換、裏面カリングを行い、三角形が覆うピクセルを列挙する。頂点の属性（法線、UV など）はピクセル位置に応じて補間される。
  4. ピクセルシェーダー (PS): ピクセルごとに実行され、色を計算する。ライティングやテクスチャはここで行う。
  5. 出力マージャ (OM): 深度テストで隠面を除去し、ブレンドで既存の色と合成してレンダーターゲットに書く。
ポイント GPU が速い理由は「同じ小さなプログラムを、大量のデータに対して並列に走らせる」構造にあります。頂点シェーダーとピクセルシェーダーは、隣の頂点や隣のピクセルのことを知らずに独立して動きます。この制約を理解すると、シェーダーで「できること・できないこと」が見えてきます。

2.2 深度テスト、カリング、ブレンド

深度テスト

手前の物体が奥の物体を隠すには、ピクセルごとに「今まで描いた中で一番手前の深度」を覚えておく必要があります。これが深度バッファです。新しいピクセルの深度が記録より小さい（手前）ときだけ色と深度を更新します。本プログラムでは 24bit 深度 + 8bit ステンシルの D24_UNORM_S8_UINT 形式を使い、比較関数は LESS です。

裏面カリング

閉じた物体の裏側の面は見えないので、描画前に捨てると速くなります。三角形の表裏は、画面上での頂点の並び順（巻き順）で判定します。DirectX の既定では「画面上で時計回り」が表です。地形メッシュは上から見て時計回りになるよう頂点を並べており（第 6 章）、粒子のビルボードや全画面パスではカリングを無効にしています。

ブレンド

半透明の物体は、既に描かれている色と混ぜて書き込みます。もっとも基本的なアルファブレンドは次式です。

result = src · α + dst · (1 − α)

本プログラムでは、水面を地形の上に α = 0.9 で合成するとき（第 15 章）に使います。

2.3 DirectX 11 の主要オブジェクト

第 3 章

シェーダー入門 — HLSL で GPU をプログラムする

シェーダーは GPU 上で走る小さなプログラムです。この章では HLSL の基本文法、頂点シェーダーとピクセルシェーダーの書き方、CPU からデータを渡す定数バッファ、そして本プログラムが多用する「頂点バッファを使わない描画」を学びます。

3.1 HLSL の基本

HLSL（High Level Shading Language）は C に似た文法で、float3, float4x4 のようなベクトル・行列型が組み込まれています。よく使う要素を挙げます。

要素例と意味
ベクトル型float2 float3 float4 int2 uint。v.xyz, v.xy のように成分を自由に取り出せる（スウィズル）
行列型と積float4x4 M; mul(v, M)。M._m00 で要素にアクセス
組み込み関数dot cross normalize length saturate lerp pow exp sqrt clamp
セマンティクス: POSITION, : SV_POSITION など。入出力の「意味」をパイプラインに伝えるラベル
リソースTexture2D, SamplerState, StructuredBuffer<T>, cbuffer
レジスタregister(b0)（定数）, register(t0)（テクスチャ/バッファ）, register(s0)（サンプラー）。CPU 側の PSSetShaderResources(0, ...) の番号と対応

3.4 頂点バッファを使わない描画

頂点シェーダーには、頂点バッファの代わりに「何番目の頂点か」（SV_VertexID）と「何番目のインスタンスか」（SV_InstanceID）を受け取る方法があります。座標を番号から計算できるなら、頂点バッファは不要です。本プログラムはこれを 2 か所で使います。

全画面三角形

後処理（ぼかしや合成）では画面全体を覆う面を描きます。四角形（三角形 2 枚）でもよいのですが、大きな三角形 1 枚のほうが対角線上でピクセルが 2 回処理される無駄がなく、頂点バッファも要りません。

{{CODE:shaders/Common.hlsli:FullscreenVSOut VSFullscreen(uint vid : SV_VertexID):}}

vid = 0, 1, 2 に対して uv は (0,0), (2,0), (0,2) となり、クリップ座標は (−1,1), (3,1), (−1,−3)。画面（−1〜1）の外にはみ出した部分はクリップされ、画面全体がちょうど覆われます。

インスタンシング

同じ形状を何千個も描くとき、1 個ずつ描画命令を出すと CPU がボトルネックになります。DrawInstanced(頂点数, インスタンス数) は 1 回の命令で N 個描き、頂点シェーダーは SV_InstanceID で「今どの個体か」を知ります。粒子の描画（第 14 章）では、粒子の位置を StructuredBuffer に入れておき、Particles[iid] で読み出します。

第 4 章

ライティングとテクスチャ

同じ形でも、光の当たり方と表面の模様で見え方はまったく変わります。この章では、面の向きと光の方向から明るさを求める「ライティング」の基本モデルと、画像を面に貼る「テクスチャマッピング」を、地形と水面の描画コードで学びます。

4.1 法線 — 面の向き

ライティングの出発点は、面がどちらを向いているかを表す単位ベクトル、法線 N です。三角形の法線は 2 辺の外積で求まりますが、滑らかな曲面に見せたい場合は、頂点ごとに周囲の面の法線を平均した「頂点法線」を持たせ、ラスタライザに補間させます。高さマップ地形では、高さの偏微分から直接求めることができます（第 6 章）。

4.2 ランバート拡散反射

ざらざらした面は光をあらゆる方向に均等に散らします（拡散反射）。その明るさは、面に光が「どれだけ正面から当たるか」で決まり、法線 N と光源へ向かう方向 L の内積で表せます。

Idiffuse = max(0, N·L) = max(0, cos θ)
図 4-1 ランバート拡散反射

max(0, …) は、光が裏側から当たる場合（内積が負）を 0 にするためです。実際にはこれに環境光（あらゆる方向から回り込む光の近似）を足し、真っ暗な部分を作らないようにします。地形シェーダーでは、上を向いた面ほど空からの光を受けるという「半球ライティング」風の環境光を使っています。

4.3 鏡面反射 — Blinn-Phong

つやのある面には、光源の像がハイライトとして映ります。視線方向 V と光源方向 L のちょうど中間の向き H（ハーフベクトル）を法線がどれだけ向いているかで、ハイライトの強さを近似するのが Blinn-Phong モデルです。

H = normalize(L + V),   Ispec = max(0, N·H)n

指数 n が大きいほどハイライトは小さく鋭くなります（粒子: 40、水面: 48）。

4.4 フレネル反射

水面を斜めから見ると鏡のように空を映し、真上から見ると透けて見えます。この「見る角度で反射率が変わる」現象がフレネル反射で、Schlick の近似式で簡単に計算できます。

F = F0 + (1 − F0)(1 − N·V)5

F0 は正面から見たときの反射率（水は約 0.02〜0.06）です。第 15 章の水面シェーダーでは指数 4、F0 = 0.06 とし、フレネル項の分だけ空の色を混ぜています。

4.5 テクスチャマッピング

面に画像を貼るには、各頂点に「画像のどの位置に対応するか」を示すテクスチャ座標（UV、0〜1）を持たせます。ラスタライザが UV を補間し、ピクセルシェーダーで Texture.Sample(sampler, uv) と書けば、その位置の色が取れます。

サンプラーの設定

設定意味本プログラム
アドレスモードUV が 0〜1 を外れたときの扱い。WRAP は繰り返し、CLAMP は端で固定地形: WRAP、深度テクスチャ: CLAMP
フィルタピクセルの中心が画素の間にあるときの補間。POINT は最近傍、LINEAR は線形補間、ANISOTROPIC は斜めから見た面の補間を改善地形: 異方性 8、深度: POINT
ミップマップ画像を 1/2, 1/4, … と縮小した系列を用意し、遠くの面には小さい画像を使う。縮小時のちらつき（エイリアシング）を防ぐGenerateMips で自動生成
コラム: なぜミップマップが必要か 遠くの地形では、1 ピクセルの中にテクスチャの何十画素分もが収まります。そのうち 1 点だけを拾うと、カメラが少し動くたびに拾う画素が変わってちらつきます。あらかじめ縮小して平均した画像（ミップ）を使えば、1 ピクセルに対応する範囲の平均色が得られます。GPU は UV の変化率から適切なミップレベルを自動で選びます。

繰り返し感の低減

1 枚のテクスチャを WRAP で敷き詰めると、同じ模様の繰り返しが目につきます。地形シェーダーでは、別スケール・別オフセットでもう一度サンプルして乗算し、周期を崩しています。
