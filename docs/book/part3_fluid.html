第 III 部

流体編

水を「粒子の集まり」として計算する SPH 法。
その考え方から、速く・安定に動かすための実装技術まで。

第 9 章

粒子で流体を表す — 粒子法の考え方

水の動きをコンピュータで計算するには、連続した「流体」を有限個の数値で表す必要があります。この章では、流体シミュレーションの 2 つの流儀（格子法と粒子法）と、粒子法の代表である SPH の基本的な考え方を、数式を最小限にして説明します。

9.1 流体の運動方程式

流体の運動はナビエ・ストークス方程式で記述されます。難しそうな名前ですが、中身はニュートンの運動方程式 ma = F を流体に当てはめたものです。

ρ (dv/dt) = −∇p + μ∇2v + ρg

左辺は「密度 × 加速度」、右辺は流体にはたらく 3 つの力です。

項名前意味
−∇p圧力勾配力圧力の高い所から低い所へ押される。流体が「詰まりすぎない」ようにする力
μ∇2v粘性力周囲との速度差を減らす。粘りけ
ρg外力（重力）下向きに引かれる

この式を「どの場所で」計算するかで 2 つの流儀に分かれます。

  • 格子法（オイラー的）: 空間を格子に切り、各格子で流速や圧力を追う。気体や大規模な水面に向くが、飛沫や自由表面の追跡が難しい。
  • 粒子法（ラグランジュ的）: 流体を粒子に分け、粒子が流れに乗って動く。自由表面や飛沫が自然に表現でき、境界の扱いも直感的。本書はこちら。

9.2 SPH の基本アイデア — 「なめらかな粒子」

粒子法の代表 SPH（Smoothed Particle Hydrodynamics）は、もともと天体物理学で星の形成を計算するために生まれ、後に CG に持ち込まれました（Müller ら、2003）。核心は次の 1 つの考え方です。

ポイント 各粒子は「点」ではなく、半径 h の範囲にぼんやり広がった質量の塊とみなす。ある場所の物理量（密度など）は、その場所を覆っている粒子たちの寄与を「距離が近いほど大きい重み」で足し合わせて求める。
図 9-1 SPH の補間。粒子 i の値は、半径 h 内の粒子の重み付き和

この「重み付き和」の式を使えば、密度も圧力の勾配も粘性も、すべて近傍粒子の和として計算できます。微分方程式を解く代わりに「粒子ごとの足し算」に置き換わるのが SPH の魅力です。

9.3 1 ステップの流れ

SPH の時間発展は、毎ステップ次の手順を繰り返します。第 10 章以降で各段を詳しく見ます。

  1. 各粒子の近傍（距離 < h）を見つける（第 11 章）
  2. 密度 ρ を計算し、状態方程式から圧力 p を求める
  3. 圧力力・粘性力・重力から加速度を求める
  4. 速度と位置を更新する（時間積分）
  5. 地形・壁との衝突を処理する（第 12 章）
コラム: なぜ「弱圧縮性」なのか 本当の水はほとんど圧縮しません（非圧縮）。しかし非圧縮を厳密に守るには連立方程式を反復で解く必要があり、計算が重くなります。CG では「少しだけ圧縮を許し、圧縮したら強い圧力で押し返す」という弱圧縮性 SPH（WCSPH）がよく使われます。本プログラムもこの方式で、圧縮率は約 0.5% です。厳密な非圧縮手法（PCISPH, DFSPH）は第 18 章で紹介します。
第 10 章

SPH の理論と実装

前章のアイデアを具体的な数式にし、コードに落とします。カーネル関数の選び方、密度と圧力、力の計算、時間積分、そしてパラメータの決め方まで、実装と 1 対 1 に対応させて解説します。

10.1 カーネル関数

カーネル W(r, h) は「距離 r の粒子の重み」を決める関数で、r ≥ h で 0、全空間で積分すると 1 になるよう正規化されています。Müller らは用途ごとに 3 種類を使い分けました。

Wpoly6(r) = 315 / (64πh9) · (h2 − r2)3  … 密度用
∇Wspiky(r) = −45 / (πh6) · (h − r)2 · r̂  … 圧力用
∇2Wvisc(r) = 45 / (πh6) · (h − r)  … 粘性用
{{SVG_KERNELS}}
  • poly6 は r2 だけで計算でき平方根が不要。密度の和に向く。
  • poly6 の勾配は r → 0 で 0 になるため、粒子が重なると押し返す力が消えて凝集してしまう。spiky は中心で勾配が最大なので圧力力に使う。
  • visc のラプラシアンは常に正で、粘性力が必ず速度差を減らす向きにはたらく（数値的に安定）。

係数は h から起動時に 1 回だけ計算します。

10.2 密度と圧力

密度は「質量の重み付き和」です。自分自身（r = 0）も含めます。

ρi = Σj m Wpoly6(rij),   pi = k · max(ρi − ρ0, 0)

圧力は状態方程式で密度から直接決めます。静止密度 ρ0（水なら 1000 kg/m3）より詰まっていれば正の圧力が生じ、粒子同士を押し離します。負の圧力（引力）を許すと粒子が塊になって不自然になるので、0 で打ち切ります。

10.3 力と加速度

fip = −Σj≠i m (pi + pj) / (2ρj) · ∇Wspiky(rij)
fiv = μ Σj≠i m (vj − vi) / ρj · ∇2Wvisc(rij)
ai = (fip + fiv) / ρi + g

圧力力の (pi + pj)/2 は「2 粒子の圧力の平均」で、作用・反作用が対称になる（粒子 i が j を押す力と j が i を押す力が等しい）ようにした形です。∇W は j から i へ向かうので、圧力力は常に離れる向き（斥力）になります。

10.4 時間積分

加速度から速度と位置を進めます。もっとも簡単なシンプレクティック・オイラー法（速度を先に更新し、その新しい速度で位置を更新する）を使います。

v ← v + aΔt,   x ← x + vΔt

「位置を先に更新する」普通のオイラー法と比べて、エネルギーが増え続ける（爆発する）傾向が小さく、粒子系では標準的な選択です。

10.5 時間刻みと CFL 条件

Δt は大きいほど速く計算できますが、大きすぎると発散します。目安となるのが CFL 条件「1 ステップで情報が伝わる距離が h を超えてはならない」です。圧力波は音速 c = √k で伝わるので、

Δt < 0.4 h / (c + vmax) ≈ 0.4 × 0.6 / (45 + 10) ≈ 0.0044 s

本プログラムは Δt = 0.003 s です。1 フレーム（1/60 s）を複数のサブステップに分けて進めますが、処理落ちでフレーム時間が伸びるとサブステップが増えてさらに遅くなる悪循環（死のスパイラル）に陥ります。そこでサブステップ数に上限を設け、上限に達したら実時間より遅く進めます。

第 11 章

近傍探索 — 空間ハッシュとカウンティングソート

SPH の計算時間のほとんどは「半径 h 内の粒子を見つける」ことに費やされます。この章では、全対全の O(N²) を避けるための格子分割、無限空間を固定サイズの表に写す空間ハッシュ、動的メモリ確保なしで格子を作るカウンティングソートを学びます。

11.1 なぜ工夫が必要か

粒子 12,000 個で全対全の距離を調べると 1.4 億回/ステップ、1 秒間に 300 ステップなら 430 億回で、CPU では到底間に合いません。しかし距離 h 以上の粒子は寄与 0 なので、「近くにいる可能性のある粒子」だけを調べれば十分です。

11.2 一様格子と 27 セル走査

空間を一辺 h の立方体セルに切り、各粒子をセルに登録します。粒子 i の近傍は、i のいるセルと隣接する 26 セル、合計 27 セルの中にしかありません。

11.3 空間ハッシュ

地形全体を格子で埋めると 100 万セル以上になり、毎ステップのクリアが重くなります。代わりにセル座標をハッシュ関数で固定サイズの表（粒子数の 2 倍程度）に写します。空のセルはメモリを消費しません。

(cx, cy, cz) = ⌊x / h⌋,   key = (cx·73856093 ⊕ cy·19349663 ⊕ cz·83492791) & (tableSize − 1)

3 つの大きな素数を掛けて XOR する Teschner らのハッシュです。表のサイズを 2 のべき乗にすると、剰余（%、遅い）をビットマスク（&、速い）で置き換えられます。

第 12 章

境界処理・安定化・エミッタ

流体は地形や壁に当たります。この章では地形との衝突処理、粒子が谷から飛び出さないようにするための 3 つの安定化手法、そして水を投入し続けるエミッタと排水の仕組みを学びます。

12.1 地形との衝突

粒子の中心が「地面の高さ + 粒子半径」より低くなったら、その高さまで押し戻し、地面にめり込む向きの速度成分を取り除きます。

図 12-1 地形との衝突処理
v ← v − (1 + e)(v·n)n  （v·n < 0 のとき。e = 反発係数、本プログラムは 0）

(v·n)n は速度の法線方向成分です。これを引くと、地面に沿って滑る成分だけが残ります。e = 1 なら完全弾性衝突（跳ね返る）、0 なら跳ね返らずに滑ります。

12.2 飛び出しを防ぐ 3 つの安定化

基本の衝突処理だけでは、壁際で密度が急上昇したときの圧力の「蹴り」で粒子が谷の外へ飛散しました。次の 3 手法で解消しています。

加速度クランプ圧力・粘性による加速度の大きさに上限。1 ステップの速度変化を 0.75 m/s に制限（重力は別に加算）maxAcceleration = 250
接触ゾーン減衰地面から 0.3 m 以内では、地面に近いほど強く速度を減衰（最下部で 6%/ステップ、上端で 0）。跳ね上がりを吸収contactZone, contactDamping
孤立粒子の空気抵抗近傍が 8 個未満の粒子（飛沫）に 1.5%/ステップの減衰。勢いを失ってすぐ流れに戻るairDrag, sparseNeighbors

第 13 章

OpenMP による並列化

SPH の粒子ごとの計算は互いに独立なので、CPU の複数コアで同時に処理できます。この章では、コンパイラ指示子だけで並列化できる OpenMP の使い方と、並列化してよい処理・してはいけない処理の見分け方を学びます。

13.1 OpenMP とは

OpenMP は、#pragma omp parallel for を for 文の前に書くだけで、その繰り返しを複数スレッドに分配してくれる仕組みです。Visual Studio では /openmp オプション（プロジェクト設定「OpenMP のサポート」）を有効にします。

#pragma omp parallel for schedule(dynamic, 64)
for (int i = 0; i < n; ++i)
{
    // i 番目の粒子の処理。他の i の結果に依存しないこと
}
  • schedule(dynamic, 64): 64 個ずつの塊をスレッドが空き次第取っていく。粒子ごとに近傍数が違い処理時間が不均一なので、静的な等分割より効率がよい。
  • ループ変数は int の符号付き整数、ループ回数はループ開始前に決まっている必要がある。

13.2 データ競合 — 並列化してよい処理の条件

2 つのスレッドが同じ変数に同時に書き込むと、結果が壊れます（データ競合）。並列化してよいのは「各 i が自分の要素にだけ書き、他の要素は読むだけ」の処理です。

処理並列理由
セル座標・ハッシュ計算○m_cell[i], m_cellKey[i] に書くだけ
カウント・累積和・振り分け×cellStart[key]++ は複数の i が同じ key に書く（競合）。粒子数が少ないので逐次で十分
近傍リスト作成○自分のリストに書くだけ。位置は読むだけ
密度・圧力○m_density[i], m_pressure[i] に書くだけ
力○m_acc[i] に書くだけ。他粒子の圧力・速度は読むだけ
積分・衝突○m_pos[i], m_vel[i]。地形の高さマップは読むだけ
排水（削除）×配列の詰め直しは順序に依存する
「対称な力を両方の粒子に加算する」最適化はできない 作用・反作用を利用して i-j の対を 1 回だけ計算し両方に足す方法は、m_acc[j] への書き込みが競合するため、そのままでは並列化できません。本プログラムは各粒子が自分の力だけを計算する（対を 2 回計算する）代わりに、競合ゼロで並列化しています。

13.3 効果

8 論理コアの CPU で、12,000 粒子・5 サブステップ/フレームの SPH が 1 フレーム 8〜15 ms で計算できています。粒子数に対して処理時間はほぼ線形に増えるので、コア数が多いマシンではそのぶん粒子を増やせます。さらに 10 倍以上を目指すなら GPU のコンピュートシェーダーへの移植になります（第 18 章）。
